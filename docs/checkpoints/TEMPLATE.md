# CP-### — Checkpoint name

**Status: NOT STARTED** · [Master tracker](../ROADMAP.md)

Copy this template for an approved checkpoint. Use the
[reporting rules](../ROADMAP.md#verification-and-reporting) for statuses and
evidence. Replace the instructions below with the checkpoint's contract.

## Objective

Describe the result this checkpoint should achieve and why it matters.

## In scope

List the work approved for this checkpoint.

## Out of scope

Identify related work that is excluded or deferred.

## Acceptance criteria

Use checkboxes for observable conditions required for completion. Keep the
approved requirements intact as work progresses.

## Verification

Explain how each acceptance criterion will be checked. Name the commands,
manual steps, or reviews needed, including any limits on the procedure.

## Completion evidence

Record no results until checks are performed. Then add E-001, E-002, and so on
within this checkpoint, recording the check, actual outcome, status, and
contributor who performed or reported it. Include dates, revisions, logs, and
limitations when available.

## Exit decision

Record the decision, reason, and evidence references. PASS requires every
acceptance criterion to be met and approval for closure. Record FAIL
for failed checks or BLOCKED when a dependency prevents progress. If no exit
decision has been made, say so and retain the current status.

In the format of:
Status: **STATUS HERE**.
